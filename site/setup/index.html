Set up Daily Focus

Install it, open it, and answer a few questions. This page covers what to have ready, how to keep it running, and what to do if something gets in the way.

What you need

  • Claude Code or Codex, installed and signed in

    It reads your sources and writes the brief. Claude Code needs a paid Claude plan. Codex needs ChatGPT Plus or higher, and version 0.144.0 or newer.

  • A Mac with Apple silicon, or Node.js

    The menu bar app needs macOS 13.5 or newer and brings everything else with it. On any other computer, you need Node.js 22.18 or newer; 24 is recommended.

  • If you use GitHub or Jira: their command-line tools

    The GitHub CLI lets the morning brief read your pull requests and review requests, and gives you the Pull requests tab. The Atlassian CLI gives you the Jira tickets tab; for Jira in the brief, an Atlassian connector in Claude Code or Codex does as well. Skip whichever you don’t use.

Install

On a Mac

  1. Download the app. Download for Mac
  2. Open the disk image, drag Daily Focus to Applications, and open it from there.
  3. It lives in the menu bar, with no window or Dock icon. Click the bullseye and choose Open Daily Focus.
  4. In the same menu, tick Open at Login, so it’s running when the brief is due.

With Node.js

  1. Run it from a terminal.
    npx daily-focus
  2. Your browser opens on localhost:4321.
  3. Keep the terminal open: the brief is written only while Daily Focus runs. On a Mac, a background service keeps it running for you.

Either way, Daily Focus opens on a setup screen that asks a few questions, one at a time, with the likely answer already ticked. You can change every answer later on the settings page.

Keep it running

The morning brief is written only while Daily Focus runs. If it wasn’t running at the time you chose, it writes the brief as soon as it starts that day. Use one of these, not both.

With the menu bar app

Tick Open at Login in its menu. The app then starts Daily Focus when you log in, and starts it again if it stops.

As a background service on a Mac

Without the app, install Daily Focus and let macOS run it at every login, and again after a crash:

npm install -g daily-focus daily-focus service

Install it globally first; the service won’t run from npx. Run daily-focus service again after updating or switching Node.js versions, and daily-focus service --remove to stop and remove it.

On other computers

Keep daily-focus running in a terminal, or start it with your system’s own service manager.

Connect your tools

All optional. Daily Focus reads what you’re already signed in to.

GitHub

gh auth login

If your organisation uses SAML single sign-on, authorise the token for it, or the board reports that GitHub refused the read.

Jira

acli jira auth login

Calendar on a Mac

The live agenda reads Calendar.app, so a meeting moved during the day shows at once. macOS asks for calendar access the first time.

Your other sources

The morning brief can read anything Claude Code or Codex can reach. With Codex, that’s the apps linked to your ChatGPT account. With Claude Code, add each connector to Tools Claude Code may use under Morning agent on the settings page, or the brief reports it as out of reach.

Google Tasks has no connector, so it takes a small export to Google Drive first. The Apps Script guide sets it up in a few minutes.

A dashboard for home

Daily Focus can brief your personal life too: family calendars, reminders, messages, paperwork and your own projects. Run a second one, with its own data and port, and answer Your personal life when its setup asks what to brief. The menu bar app runs one, so run the other as a service beside it:

daily-focus service --data ~/.daily-focus-personal --port 4322

Reach it from your other devices

Personal sources often live on one computer, such as a Mac at home with your messages and reminders. Run Daily Focus there and reach it through Tailscale Serve, which only your own devices can use:

tailscale serve --bg http://127.0.0.1:4321

Don’t open it to your local network instead. Daily Focus has no login, and a personal brief holds your mail and messages.

Where it keeps things

Three options say where Daily Focus keeps your data and how it listens. Give them when you start it, as flags or environment variables; a flag wins. Most people never change them. Everything else is on the settings page.

FlagVariableDefaultWhat it’s for
--dataDAILY_FOCUS_DATA~/.daily-focusWhere your briefs, notes and settings live
--portDAILY_FOCUS_PORT4321The port it listens on
--hostDAILY_FOCUS_HOST127.0.0.1Your computer only, by default. A name given here is one more it answers to

Commands

daily-focusStart Daily Focus and open it in your browser
daily-focus serviceKeep it running in the background on a Mac; --remove takes it away
daily-focus initCreate the data folder with an objective and a source list to fill in by hand

daily-focus --help lists every command and flag.

Update

The menu bar app looks for new releases a few times a day and offers each one in its menu, under Updates. Choose Update Automatically there to have them go in on their own while you’re not using it, or Development Builds to get every change as soon as it’s merged.

With Node.js, npx daily-focus@latest runs the newest version. If you installed it globally, update it and restart the service:

npm install -g daily-focus daily-focus service

Uninstall

The menu bar app: choose Quit Daily Focus from its menu, then move the app to the Trash.

The service:

daily-focus service --remove npm uninstall -g daily-focus

Your briefs, notes and settings stay in ~/.daily-focus, and what the app downloaded in ~/Library/Application Support/Daily Focus. Delete both folders to remove everything.

If something gets in the way

Setup can’t find Claude Code or Codex
The setup screen says what’s wrong with each and the command that fixes it, such as claude auth login or codex login. If it’s installed somewhere unusual, give setup its path.
Daily Focus is gone after a restart
It was probably started in a terminal and ended with it. Use the menu bar app or the background service to keep it running.
The page doesn’t load
With the app, choose Restart Dashboard from its menu, or Show Log to see why. With the service, read ~/Library/Logs/local.daily-focus.log.
The menu says “Run by another process”
A service or a terminal is running Daily Focus, and the app only watches it. Stop the other one, then quit and reopen the app.
Port 4321 is in use
Another program has it. Stop that program, or start Daily Focus on another port with --port 4322.
The GitHub or Jira board shows a warning
Sign in again with gh auth login or acli jira auth login. If Daily Focus can’t find the tool at all, give its path on the settings page.
A source is missing from the brief
The run’s report, behind “updated … ago” on the Today tab, names the sources it couldn’t reach. Under Claude Code, add the connector to the tools it may use.
